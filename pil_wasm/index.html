About this build — what works, what doesn't

This is Alexander Burger's PicoLisp (pil21) compiled to WebAssembly and running entirely in your browser. No server evaluates anything; reloading the page gives you a fresh, empty interpreter.

It is the bare interpreter. There is no filesystem and lib.l is not loaded, so the following are not available:

  • load, and in/out on files
  • everything from lib.l and the @lib/* modules (pilog, http, xhtml…)
  • the database layer, native/FFI, and subprocesses

The core language is all there: arithmetic and bignums, lists, strings and symbols, de, let, mapping functions, catch/throw, error recovery and gc.

Note that (bye) ends the interpreter for the tab — you will be told to reload.

Steps to reproduce this build

Everything you need is in one 34KB archive: pil21-wasm64.tar.gz — the files this port adds to a stock pil21 tree, plus a patch for the single file it modifies. Unpack it over a pil21 source tree:

tar -xzf pil21-wasm64.tar.gz --strip-components=1
patch -p1 < src/dec.l.patch

1. Toolchain. Emscripten 6.0.9 via emsdk. The native pil21 build is needed first, so you also need its usual dependencies (clang/LLVM, readline, libffi, OpenSSL). Node 24 is only needed for the Node build and the test harness.

git clone https://github.com/emscripten-core/emsdk.git ~/src/emsdk
cd ~/src/emsdk && ./emsdk install 6.0.9 && ./emsdk activate 6.0.9
source ~/src/emsdk/emsdk_env.sh

2. Build native pil21 first. This bootstraps src/base.ll, the target-independent LLVM IR that the wasm build consumes. (The release tarball ships a base.ll, so this step can be skipped if you do not want the native binary.)

cd src && make

3. Build for wasm. These targets are not in the stock pil21 Makefile. They come from src/Makefile.wasm, which this port adds; the stock src/Makefile is left untouched, so the native build is unaffected.

make -f Makefile.wasm browser   # -> ../bin/web/{index.html,picolisp.js,picolisp.wasm}
make -f Makefile.wasm wasm      # optional: Node build -> ../bin/picolisp.js

4. Serve it over HTTP. WebAssembly cannot be fetched from a file:// URL, so opening the HTML directly will not work. Any static server will do; only those three files need to be deployed, and they must stay in the same directory.

cd ../bin/web && python3 -m http.server 8765

Verifying a build. The native binary is the oracle — run the same script through both and diff. They should be byte-identical:

./bin/picolisp                < script.l > /tmp/out.native 2>&1
node src/browser/test-node.js < script.l > /tmp/out.browser
diff /tmp/out.native /tmp/out.browser

src/browser/test-node.js drives this browser build headlessly through the same three hooks the page uses, so the wasm side is testable without a browser.

What it took to get pil21 onto wasm64

pil21 stores type tags in the low bits of 64-bit pointers, so this has to be wasm64 (-sMEMORY64=1); wasm32 is not an option, and neither is wasi-sdk, which does not support wasm64. The substantive problems were:

  • Heap alignment. Cells must be 16-byte aligned because tags live in ptr & 15, but Emscripten's wasm64 malloc is only 8-byte aligned — malloc(36) % 16 == 8. A heap segment landing on an 8-mod-16 address makes every cell read back as a symbol. pil21's allocator is routed through a 16-byte aligned one. This one is nasty because it depends only on prior allocation history, so it appears and disappears with unrelated edits.
  • call_indirect signatures. PicoLisp's dispatch passes two arguments where builtins declare one. x86-64 ignores the extra argument; wasm traps. A dummy parameter is added to the IR.
  • Function-pointer tagging. PicoLisp tags function pointers +2 and untags with & ~3, which needs 4-byte-aligned addresses; wasm table indices are sequential integers. An in-memory indirection table restores the invariant.
  • Blocking stdin. A browser cannot block, so reading a character suspends the whole interpreter through Asyncify and resumes it when a keystroke arrives. Asyncify also covers pil21's setjmp/longjmp.
  • Console I/O. Env.put/Env.get are intercepted directly, bypassing the Emscripten filesystem. A replacement reader must also maintain $Chr, PicoLisp's single-character look-ahead, or the reader rejects valid input.
  • Stack size. Emscripten defaults to 64KB against native's 8MB, and PicoLisp recurses over lists.

Three genuine pil21 portability bugs turned up on the way, in the declared types of fread, fwrite and poll (nfds_t is 64-bit on x86-64 and 32-bit on wasm64) — three lines in src/dec.l, the only change to pil21's own Lisp sources.

Everything else is additive: src/Makefile.wasm, src/wasm_patch_ll.py (which post-processes the LLVM IR), src/readline_stubs.c, this page, and src/lib.emscripten.c — a variant of src/lib.c with the libffi/dlopen layer stubbed out (hence no native) and the Emscripten-specific I/O and allocator shims added.
